# HY2 端口跳跃

> v2.3.0 新增功能。自动转发需要同时使用 xboard-u v2.3.0 和 xboard-node-u v2.3.0 或后续兼容版本；旧版 v2.2.1 节点不会自动建立规则。推荐先更新节点端，再配置范围。

## 面板填写

仅 HY2 提供该功能。节点编辑页的“连接端口”下方有“端口跳跃间隔（秒）”，占位提示为“例如：10 或 10-30，默认 30”。

| 字段 | 示例 | 含义 |
|---|---|---|
| 连接端口 | `60000-65000` | 客户端在范围内访问节点 |
| 服务端口 | `60000-65000` | 节点只监听 UDP 60000，将 UDP 60001～65000 重定向到 60000 |
| 端口跳跃间隔 | `10` | 客户端每隔 10 秒切换 |
| 端口跳跃间隔 | `10-30` | 客户端每次在 10～30 秒内重新随机选择间隔 |
| 间隔留空 | — | 默认固定 30 秒 |

- 不需要额外开关：连接端口为范围即向客户端启用跳跃；单端口时禁用间隔输入，不输出跳跃字段。
- 端口支持单个整数或一段连续范围，取值 1～65535，包含首尾；暂不支持逗号、多段范围或通配符。
- 间隔至少 5 秒，只接受整数或顺序正确的一段范围。非法输入会阻止保存。
- 相同上下限会规范化为单个值，例如 `60000-60000`、`10-10`。
- 跳跃间隔由客户端执行。服务端不会定时更换监听端口，也不会为每个端口创建一个入站。

这一转发方式参考 [Hysteria 官方端口跳跃说明](https://v2.hysteria.network/docs/advanced/Port-Hopping/)。

## 客户端与服务端分离

开启“高级设置 → CDN套用 → 客户端与服务端分离”后：

- 外层连接端口和间隔用于客户端订阅。
- 服务端范围在内层“服务端端口”填写。
- 外层只读服务端口即时展示内层完整范围。
- “同步配置”必须同时携带服务端口与范围信息；仍需分别保存高级弹窗和节点编辑窗口。
- 关闭分离后，恢复外层原有服务端配置，不继续套用隐藏的内层范围。

普通直连部署通常两侧填写相同范围。公网范围与本机范围不同，必须实际存在外部 NAT 或端口映射；仅填写不同的值不会自动建立两侧网络之间的映射。分离功能本身也不会让普通 HTTP CDN 支持 HY2 UDP。

## 手动转发或权限受限环境

如果由宿主机、运营商 NAT、容器宿主机或管理员管理映射：

- 连接端口填写公网范围。
- 服务端口填写实际的单端口，例如 `443`。
- 管理员自行将公网范围转发到该端口。
- 节点端不创建或清理这些手动规则。

填写了服务端范围则明确要求自动管理。工具或权限不足会报告错误，不会静默只启动首端口并宣称整个范围可用。

## 订阅兼容

| 客户端 | 行为 |
|---|---|
| Sing-box 1.14+ | 输出 `server_ports`、`hop_interval`，随机时增加 `hop_interval_max` |
| Sing-box 1.11～1.13 | 支持范围，随机间隔降级为固定下限 |
| 更旧或无法确认支持范围的 Sing-box 客户端 | 保留公网范围首端口，不输出未知字段 |
| 支持当前语法的 Mihomo | 输出 `ports`；随机 `hop-interval` 保留为范围字符串 |
| Stash、Surge | 按当前公开能力使用固定间隔；随机范围降级为其下限 |
| 通用分享链接 | 仅输出已确认的导入字段，具体应用能否保留间隔需要分别验证 |

例如 `10-30` 在 Stash / Surge 中输出固定 10 秒。原生 Xray 支持随机 UDPHop，不表示 v2rayNG 等应用从分享链接导入时一定保留它。服务端目标内核选择不决定客户端能力。

参考：[Sing-box](https://sing-box.sagernet.org/configuration/outbound/hysteria2/)、[Mihomo](https://wiki.metacubex.one/config/proxies/hysteria2/)、[Stash](https://stash.wiki/en/proxy-protocols/proxy-types)、[Surge](https://manual.nssurge.com/policies/hysteria2.html)、[Xray UDPHop](https://xtls.github.io/config/transports/finalmask.html#udphop)。

## 自动规则与停止清理

- 节点端优先使用可用的 nftables，无法使用时尝试 iptables / ip6tables。
- Linux 需要对应的网络管理权限；LXC 中的 root 不一定有 NET_ADMIN。
- 按监听地址处理 IPv4 / IPv6，默认 `::` 的双栈范围需要双栈可用。
- 规则只匹配入站 UDP，不占用同号 TCP 端口。
- 范围使用少量规则，不创建成千上万个监听器。
- 同机重叠范围或已有 UDP 监听冲突会被拒绝。
- 停止、重启、删除机器节点、改回单端口和卸载会清理所属自动规则；其他节点和管理员规则保留。
- 系统服务补充退出清理，进程启动也会检查并恢复异常退出留下的所属状态。
- 不能依靠退出回调保证断电或所有强制终止场景都即时清理。卸载清理失败时保留程序供恢复。
- 修改客户端间隔不会触发服务端重启或反复写入防火墙。
- 云安全组和其他防火墙仍须放行相应 UDP 范围；自动重定向不等于所有网络层已经放行。

## 升级与数据保存

现有数据库列和节点通信中的 `server_port` 仍为整数。范围首端口写入该字段，完整服务范围保存在 `protocol_settings.hy2_settings.port_range`；随机间隔保存为整数下限 `hop_interval` 与上限 `hop_interval_max`。不需要修改数据库列类型。

旧面板不下发范围时，新节点保持单端口行为。旧配置只填写了客户端范围，不会被擅自转成服务端自动规则。

带宽方向转换、BBR / Brutal、证书、Masquerade、用户和流量统计保持原有逻辑。所有跳跃端口进入同一个入站，不会每个端口各算一个节点。

游戏加速建议先以稳定的单端口作对比，再按实际线路需要开启跳跃；本地验证不能保证所有公网线路零抖动。
