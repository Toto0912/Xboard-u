# 二次开发功能说明

xboard-u 基于原版 Xboard，配合 [xboard-node-u](https://github.com/Toto0912/xboard-node-u) 使用。本页介绍二次开发增加或调整的功能，安装和更新方式见 [README](../README.md)，发布状态见 [变更记录](../CHANGELOG.md)。

## 配置界面修正（v2.1.2）

CDN 分离开启时，外层只读服务端口与节点列表内部端口统一显示实际服务端监听端口；客户端连接端口保持独立，关闭分离时恢复原外层服务端口草稿。

「根据内核生成示例」使用与 [自定义出站](CUSTOM-OUTBOUNDS.md)、[自定义路由](CUSTOM-ROUTES.md) 文档一致的 Xray 原生配置：SOCKS 出站直接填写 `settings.address/port/user/pass`，路由省略旧式 `type: "field"`。路由示例自动使用实际服务端监听端口，原有 `servers/users` 出站和带 `type` 的路由配置仍兼容。

## 稳定性与性能优化（v2.1.0）

设备状态按节点维护完整快照，在线心跳刷新有效期，空快照及时清理，旧 WebSocket 的关闭事件不会清除新连接状态。Redis 增加节点成员索引并批量读取，已有设备缓存会自动导入索引。

在线计数、用户流量和统计改为批量写入，减少重复数据库操作。节点列表批量读取缓存、父节点和权限组；Horizon 小预算使用共享池并关闭额外默认进程。修正节点排行日期范围，并保留升级前已入队统计任务的兼容处理。

本版本无需新增配置或数据库迁移，安装与更新命令不变。配套 xboard-node-u v2.1.0 可获得完整的设备心跳及重连修复。

默认向节点下发 `listen_ip: "::"`，在启用 IPv6、允许双栈套接字的系统上同时监听 IPv4 和 IPv6。单节点、机器模式的 REST/WebSocket 配置及 CDN 分离后的服务端配置均使用该默认值；公网连接还需服务器具备对应地址、路由并放行端口。已安装先前 v2.1.0 的面板需要重新拉取镜像并重建服务，节点重新拉取配置后生效。

## CDN 套用（v2.0.0）

在「节点管理 → 编辑节点 → 高级设置 → CDN套用」中开启「客户端与服务端分离」。外层设置订阅使用的地址、连接端口、安全性和传输。内层设置 xboard-node-u 使用的监听端口及服务端连接参数。两侧共用节点 ID 和协议，权限、机器绑定、计费、证书、路由和出站继续使用原有入口。

分离开启时，外层「服务端口」只读展示内层的实际监听端口，节点列表「内部端口」也显示相同值；在高级设置中保存新的监听端口后，外层显示随之更新。客户端连接端口保持独立，关闭分离后恢复显示原外层服务端口草稿。

例如，外层配置 `edge.example.test:443`、TLS 和 XHTTP `/xhttp`。内层配置监听 `9443`、明文和 XHTTP `/xhttp`。反向代理终止 TLS 并将请求转发到 9443，订阅刷新后客户端仍连接 443。服务端「节点地址」供既有配置生成逻辑使用，监听地址由节点端决定。

首次开启会复制当前外层草稿。再次开启恢复停用时保留的服务端草稿。「同步配置」以当前外层草稿覆盖内层连接字段，保留服务端 Reality 私钥、目标站与 Fallback。跨内核同步可转换 TCP、WebSocket Host、gRPC 服务名称与 HTTPUpgrade 的基础字段，其余组合提示手动调整。服务端 Fallback 的适用条件按内层计算，外层只读显示。关闭分离时，符合外层条件的 Fallback 转回外层。高级设置保存后仍需点击「保存节点」才会提交到面板。

传输编辑器的「恢复默认」清除显式参数，「填入官方示例」用于学习与修改。两者都先预览覆盖范围。目标内核用于编辑和校验，节点端仍根据其实际配置及既有适配规则选择内核。订阅仍按请求的客户端格式生成。XHTTP 通用链接保留 Extra，Mihomo 对能等价表达的 XHTTP 参数生成原生选项。普通 Clash、Stash 和 Sing-box 等格式继续受各自能力限制。

### 节点编辑界面

v2.0.0 的节点编辑与高级设置采用与演示页一致的分组布局，并跟随面板原有日间／夜间按钮：日间使用白色背景，夜间使用深蓝色背景。调整仅作用于节点配置窗口。高级设置仍固定在底栏、取消按钮左侧；证书、自定义出站、自定义路由、多路复用和 CDN 套用使用图标标签栏。

节点名称与基础倍率直接显示。动态倍率、流量限制、自定义节点 ID、标签和权限组可展开「更多节点属性」编辑；父级节点、路由组与绑定服务器可展开「归属与部署」编辑。已有字段和保存规则继续保留。

CDN 页面提供卡片式分离开关、两侧连接摘要、双列端口与分组传输编辑器。窄屏自动改为单列，内容区独立滚动，底部取消和保存按钮保持可见。

### 升级与回退

1. 备份面板数据库、现有配置及两端源码。先在独立环境运行面板迁移 `php artisan migrate --force`，再启动使用新资源的面板实例。新增的可空 `v2_server.cdn_settings` 默认关闭。
2. 用 `php artisan server:audit-transports` 检查旧节点，按实际部署内核确认下表中的迁移项。命令仅读取数据库和输出节点 ID、协议及传输。
3. 用本次配套节点端源码构建节点程序。CDN 分离沿用 v1.1.3 现有节点通信结构。配套改动按实际内核校验 Xray 已移除的传输，并兼容 Sing-box 的 RAW 别名。
4. 回退旧版面板前，逐条关闭分离并恢复原有可用监听配置，确认节点和订阅后再换回旧代码。保留新增数据库列以保留草稿。

### 传输迁移范围

| 内核与配置 | 固定基线状态 | 迁移方式 |
| --- | --- | --- |
| Xray Trojan、VMess、Shadowsocks | 官方仍提供完整入站配置 | 保留协议、现有节点和 Xray Trojan Fallback。 |
| Xray WebSocket、gRPC、HTTPUpgrade | 官方仍提供传输配置 | 保留编辑和下发，按各自结构处理字段。 |
| Xray 旧 HTTP/H2/H3、旧 V2Ray QUIC | v26.10.31 解析器明确移除 | 手动选定新传输并更新两端。旧 HTTP/H2 不会改写成 XHTTP。Sing-box HTTP 保留独立语义。 |
| Xray TLS `allowInsecure: true` | v26.10.31 已移除 | 关闭跳过校验，部署可验证证书。Sing-box 同名选项按其原有规则处理。 |
| Xray WebSocket `headers.Host` | 固定源码明确标记弃用 | 旧 Xray 数据以独立 `host` 下发。Sing-box WebSocket 仍使用 `headers.Host`。 |
| Sing-box HTTP、WebSocket、gRPC、HTTPUpgrade、V2Ray QUIC | v1.14.4 的 V2Ray 传输定义保留这些类型 | 沿用已适配字段。旧 V2Ray QUIC 需要 TLS。 |

入站支持范围见 [Xray 官方入站配置](https://xtls.github.io/config/inbounds/)。固定版本源码区分运行时迁移建议、计划移除的字段和已移除的配置错误。内核依据见 [Xray v26.10.31 发布记录](https://github.com/XTLS/Xray-core/releases/tag/v26.10.31)、[固定提交传输解析器](https://github.com/XTLS/Xray-core/blob/a4a3dff5b20c/infra/conf/transport_internet.go)、[Xray TLS](https://xtls.github.io/config/transports/tls.html) 和 [Sing-box v1.14.4 传输定义](https://github.com/SagerNet/sing-box/blob/v1.14.4/option/v2ray_transport.go)。mKCP 等原生能力需要面板、节点和订阅链路配套后再开放。 Sing-box 原生请求头、WebSocket Early Data、gRPC 超时及 HTTP 高级字段随 Sing-box 订阅输出。其它输出格式遇到无法等价表达的这些字段时跳过对应节点，面板日志记录节点 ID 和客户端类型。

## Mihomo / Stash Reality 订阅（v2.1.1）

Mihomo / Clash Meta 与 Stash 订阅会自动在输出的 Reality 节点中添加以下字段。Mihomo 的 XHTTP 分离下行选择 Reality 时，也会在下行的 `reality-opts` 内添加：

```yaml
reality-opts:
  public-key: <节点公钥>
  short-id: <节点 Short ID>
  support-x25519mlkem768: true
```

此字段只在 Mihomo、Stash 订阅转换时生成，不修改面板保存的节点配置、节点端配置或其他客户端订阅；普通 TLS 和明文连接不添加。无需额外开关或手动修改订阅模板。各客户端既有协议筛选保持不变：当前 Stash 转换仍过滤 Trojan Reality，不因添加此字段而开放新协议或传输。

该选项让客户端提供 X25519MLKEM768 密钥交换能力，需使用支持此字段的客户端；实际连接仍取决于客户端版本、指纹及服务端的其他握手要求，详见 [Mihomo 官方文档](https://wiki.metacubex.one/config/proxies/tls/#reality-optssupport-x25519mlkem768) 和 [Stash 官方文档](https://stash.wiki/en/proxy-protocols/proxy-types#using-reality)。Stash 官方提示，2025 年 5 月以前发布的 Reality 服务端应关闭此选项，本功能面向当前配套的新内核服务端。

## XHTTP 上下行分离订阅（v1.1.1）

为 **VLESS + XHTTP** 补齐 Clash Meta / Mihomo 订阅转换。面板仍保存 Xray 格式的 `network_settings`，订阅时自动生成 Mihomo 原生 `xhttp-opts`，无需在客户端手动补写 `extra`。此功能从 v1.1.1 开始提供。

### 使用条件

- 节点端选择 Xray 内核，已有 xboard-node-u v1.1.0 可继续使用；无需为本次面板转换单独升级节点端。sing-box 服务端不支持 XHTTP。
- 客户端内核必须支持 XHTTP 和 `download-settings`。本次验证使用 Mihomo v1.19.33；客户端软件版本与其内核版本不一定相同。
- 两个入口须最终转发至同一个 XHTTP 服务端监听实例，并使用匹配的路径；仅填写两个域名不会自动建立反向代理或 CDN 转发。
- VLESS 的 Flow 留空。常见 CDN / 反向代理场景建议使用 `packet-up`；`stream-up` 还要求上传入口正确支持持续流式转发。`stream-one` 不能配置上下行分离。

### 配置示例

面板节点地址填写上传入口，例如 `up.example.com:443`；安全性选择 TLS，并填写上传入口对应的 SNI。传输选择 XHTTP，其 `network_settings` 可使用以下内容（示例地址均为占位值）：

```json
{
  "path": "/xhttp",
  "host": "up.example.com",
  "mode": "packet-up",
  "extra": {
    "downloadSettings": {
      "address": "down.example.com",
      "port": 443,
      "network": "xhttp",
      "security": "tls",
      "tlsSettings": {
        "serverName": "down.example.com",
        "alpn": ["h2"]
      },
      "xhttpSettings": {
        "path": "/xhttp",
        "host": "down.example.com"
      }
    }
  }
}
```

上传和下载域名、端口、HTTP Host 与 TLS SNI 应分别匹配各自入口；TLS 使用有效且匹配域名的证书。Xray 26.10.31 已移除 `tlsSettings.allowInsecure: true`，不要在上述原始配置中使用它来跳过校验。下行 `downloadSettings` 按独立连接填写，须提供 `address`、有效 `port` 和 `network: xhttp`；不填写 `security` 时为明文，不会继承上传入口的 TLS。

转换后，Mihomo 节点的关键字段如下；完整订阅还会显式设置下行默认值，防止意外继承上行参数：

```yaml
network: xhttp
xhttp-opts:
  path: /xhttp
  host: up.example.com
  mode: packet-up
  download-settings:
    server: down.example.com
    port: 443
    tls: true
    servername: down.example.com
    alpn: [h2]
    path: /xhttp
    host: down.example.com
```

下行使用 Reality 时，改为 `security: reality`，在 `realitySettings` 填写 `serverName`、`fingerprint`、`publicKey`（或新版 `password` 字段）及 `shortId`。这些是客户端公钥参数，不要填写服务端私钥。

### 转换范围与兼容性

- 支持常用请求头、填充、会话/序号/上传数据位置、POST 大小及间隔，并将 `xmux` 转为 `reuse-settings`；下行独立转换地址、端口、TLS / Reality、SNI、ALPN、指纹、请求头和 XMUX。
- 下行不会误继承上传入口的 Reality、ECH、SNI、证书校验、请求头、路径或 XMUX。明文下行按 Xray 默认使用 HTTP/1.1，TLS 下行按自身 ALPN 选择版本。需要沿用相同值时，按 Xray 规则在下行配置中明确填写。
- Mihomo 下行只提供部分独立传输选项。下行另设不兼容的填充/会话参数、非空 `h2Params`、嵌套分离、无法等价表达的 TLS 选项（例如 Xray 专用证书固定校验），或输入格式错误时，该节点会从 Mihomo 订阅中跳过；面板日志记录节点 ID 及原因，不记录整份配置或密钥。其他有效节点继续生成，不会偷偷改回普通 XHTTP。
- 不改变原始节点配置及机器/单节点通信格式。通用 VLESS 分享链接继续保留 Xray `extra`；sing-box、普通 Clash、Stash 沿用各自转换逻辑，本次不会向它们注入 Mihomo 专用字段。这不代表这些客户端均支持 XHTTP。
- 不更换已有默认/自定义订阅模板，不修改数据库结构，也不需要重新安装面板。

## 节点 Fallback

支持 VLESS / Trojan，传输为 TCP/RAW，安全性为 TLS 或 Reality。符合这些条件时，编辑节点的安全性设置下方、传输协议设置上方会显示可选的 `Fallback` 输入框；切换为其他传输或关闭安全性时隐藏。

填写 `域名:端口`、`IP:端口` 或 `[IPv6]:端口`，例如 `site.example.com:443`、`127.0.0.1:8080`、`[::1]:8443`。有效输入会保存并下发；空值、格式不正确或不适用当前协议组合的输入，在保存时按空值处理，不阻止保存节点。

面板和节点端均须使用包含此功能的版本。Xray 内核的机器模式、单节点模式都支持；sing-box 节点忽略此项。该配置只供服务端使用，不写入客户端订阅，也不改变客户端连接地址、SNI 或 Reality 公钥。

### TLS 普通回落

填写 TLS 解密后的后端地址，例如本机明文 HTTP 网站 `127.0.0.1:8080`。Xray 配置协议层回落，默认协商 HTTP/1.1；浏览器访问节点的 HTTPS 端口时，非代理请求进入网站，合法代理请求照常使用。

TLS、Reality 的协议层回落均不能与 VLESS 额外加密同时启用。存在不兼容的加密配置时，输入框禁用并提示原因，保存时清空回落配置。

### Reality 原生协议层回落（v1.1.2）

面板保留可选单目标输入框，节点端将其转换为一条原生 `fallbacks` 规则。填写接收解密后数据的后端地址，例如明文 HTTP 网站 `127.0.0.1:8080`；**不会覆盖 Reality 原目标（dest），也不改变 SNI、密钥、Short ID 或 Flow**。

- 普通浏览器或未通过 Reality 鉴权的连接仍转发到原 Reality HTTPS 目标。
- 通过 Reality 握手后，VLESS / Trojan 协议首包或认证失败的连接，才进入协议层回落。
- Reality 和代理协议认证都正确时，继续正常代理。

因此，普通浏览器访问无法验证 Reality 协议层回落是否生效。独立模式使用同一 `fallbacks` 列表语法，并支持多规则；见 [xboard-node-u 独立运行指南](https://github.com/Toto0912/xboard-node-u/blob/main/docs/STANDALONE.md)。

### 升级兼容

面板和节点端需要一并升级到 **v1.1.2**。此前版本将面板 Reality Fallback 用于覆盖 HTTPS 目标；本版有意改为原生协议层回落。旧数据仍保留，但升级前须核对已有 Reality Fallback：HTTPS 伪装目标应配置在 Reality 设置中，协议层回落通常使用明文后端，不要混用端口。回落目标不能指回节点自身监听端口。

此改动不新增数据库列或迁移，不自动删除配置。留空保持原行为；sing-box 继续忽略该服务端字段，客户端订阅不包含它。

## TLS 内容推送保存修复

修复 HY2 等节点的 TLS 内容推送配置保存后，重新打开高级设置却显示为空的问题。兼容原有空证书配置，保存并保留证书、私钥及相应设置。

## 原生自定义出站与路由（v1.1.3）

自定义路由编辑框上方只读显示当前节点的入站标签，按协议自动更新，不提供复制按钮。

面板和节点端同步升级到 v1.1.3 后，在节点高级设置中可直接填写 Sing-box 原生出站数组（type + 平铺参数），或 Xray 原生出站数组（protocol + settings 及其他原生顶层参数）。旧 protocol/settings/proxy_tag 写法继续支持，已有数据无需迁移；Sing-box 的旧 proxy_tag 转换为 detour。

原生参数不做跨内核翻译：节点端按实际内核校验，明确拒绝错用格式、未知出站引用及依赖循环；完整参数由已嵌入的实际内核解析。面板保留原生字段与空对象，不把未知字段静默删除，也不会将服务端出站和路由加入客户端订阅。

面板目前不保存每台运行实例的最终内核，保存时检查 JSON 结构，最终内核匹配与全部出站标签引用检查由节点端负责。先更新节点端，再在面板保存原生配置；旧节点端无法识别 Sing-box 原生 type 格式。

详细配置：[自定义出站](CUSTOM-OUTBOUNDS.md)、[自定义路由](CUSTOM-ROUTES.md)。
