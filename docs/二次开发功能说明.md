# 二次开发功能说明

xboard-u 基于原版 Xboard，配合 [xboard-node-u](https://github.com/Toto0912/xboard-node-u) 使用。本页介绍二次开发增加或调整的功能，安装和更新方式见 [README](../README.md)，发布状态见 [变更记录](../CHANGELOG.md)。

## XHTTP 上下行分离订阅（v1.1.1）

为 **VLESS + XHTTP** 补齐 Clash Meta / Mihomo 订阅转换。面板仍保存 Xray 格式的 `network_settings`，订阅时自动生成 Mihomo 原生 `xhttp-opts`，无需在客户端手动补写 `extra`。此功能从 v1.1.1 开始提供。

### 使用条件

- 节点端选择 Xray 内核，已有 xboard-node-u v1.1.0 可继续使用；无需为本次面板转换单独升级节点端。sing-box 服务端不支持 XHTTP。
- 客户端内核必须支持 XHTTP 和 `download-settings`。本次验证使用 Mihomo v1.19.33；客户端软件版本与其内核版本不一定相同。
- 两个入口须最终转发至同一个 XHTTP 服务端监听实例，并使用匹配的路径；仅填写两个域名不会自动建立反向代理或 CDN 转发。
- VLESS 的 Flow 留空。常见 CDN / 反向代理场景建议使用 `packet-up`；`stream-up` 还要求上传入口正确支持持续流式转发。`stream-one` 不能配置上下行分离。

### 配置示例

面板节点地址填写上传入口，例如 `up.example.com:443`；安全性选择 TLS，并填写上传入口对应的 SNI。传输选择 XHTTP，其 `network_settings` 可使用以下内容（示例地址均为占位值）：

```json
{
  "path": "/xhttp",
  "host": "up.example.com",
  "mode": "packet-up",
  "extra": {
    "downloadSettings": {
      "address": "down.example.com",
      "port": 443,
      "network": "xhttp",
      "security": "tls",
      "tlsSettings": {
        "serverName": "down.example.com",
        "alpn": ["h2"]
      },
      "xhttpSettings": {
        "path": "/xhttp",
        "host": "down.example.com"
      }
    }
  }
}
```

上传和下载域名、端口、HTTP Host 与 TLS SNI 应分别匹配各自入口；TLS 使用有效且匹配域名的证书。Xray 26.10.31 已移除 `tlsSettings.allowInsecure: true`，不要在上述原始配置中使用它来跳过校验。下行 `downloadSettings` 按独立连接填写，须提供 `address`、有效 `port` 和 `network: xhttp`；不填写 `security` 时为明文，不会继承上传入口的 TLS。

转换后，Mihomo 节点的关键字段如下；完整订阅还会显式设置下行默认值，防止意外继承上行参数：

```yaml
network: xhttp
xhttp-opts:
  path: /xhttp
  host: up.example.com
  mode: packet-up
  download-settings:
    server: down.example.com
    port: 443
    tls: true
    servername: down.example.com
    alpn: [h2]
    path: /xhttp
    host: down.example.com
```

下行使用 Reality 时，改为 `security: reality`，在 `realitySettings` 填写 `serverName`、`fingerprint`、`publicKey`（或新版 `password` 字段）及 `shortId`。这些是客户端公钥参数，不要填写服务端私钥。

### 转换范围与兼容性

- 支持常用请求头、填充、会话/序号/上传数据位置、POST 大小及间隔，并将 `xmux` 转为 `reuse-settings`；下行独立转换地址、端口、TLS / Reality、SNI、ALPN、指纹、请求头和 XMUX。
- 下行不会误继承上传入口的 Reality、ECH、SNI、证书校验、请求头、路径或 XMUX。明文下行按 Xray 默认使用 HTTP/1.1，TLS 下行按自身 ALPN 选择版本。需要沿用相同值时，按 Xray 规则在下行配置中明确填写。
- Mihomo 下行只提供部分独立传输选项。下行另设不兼容的填充/会话参数、非空 `h2Params`、嵌套分离、无法等价表达的 TLS 选项（例如 Xray 专用证书固定校验），或输入格式错误时，该节点会从 Mihomo 订阅中跳过；面板日志记录节点 ID 及原因，不记录整份配置或密钥。其他有效节点继续生成，不会偷偷改回普通 XHTTP。
- 不改变原始节点配置及机器/单节点通信格式。通用 VLESS 分享链接继续保留 Xray `extra`；sing-box、普通 Clash、Stash 沿用各自转换逻辑，本次不会向它们注入 Mihomo 专用字段。这不代表这些客户端均支持 XHTTP。
- 不更换已有默认/自定义订阅模板，不修改数据库结构，也不需要重新安装面板。

## 节点 Fallback

支持 VLESS / Trojan，传输为 TCP/RAW，安全性为 TLS 或 Reality。符合这些条件时，编辑节点的安全性设置下方、传输协议设置上方会显示可选的 `Fallback` 输入框；切换为其他传输或关闭安全性时隐藏。

填写 `域名:端口`、`IP:端口` 或 `[IPv6]:端口`，例如 `site.example.com:443`、`127.0.0.1:8080`、`[::1]:8443`。有效输入会保存并下发；空值、格式不正确或不适用当前协议组合的输入，在保存时按空值处理，不阻止保存节点。

面板和节点端均须使用包含此功能的版本。Xray 内核的机器模式、单节点模式都支持；sing-box 节点忽略此项。该配置只供服务端使用，不写入客户端订阅，也不改变客户端连接地址、SNI 或 Reality 公钥。

### TLS 普通回落

填写 TLS 解密后的后端地址，例如本机明文 HTTP 网站 `127.0.0.1:8080`。Xray 配置协议层回落，默认协商 HTTP/1.1；浏览器访问节点的 HTTPS 端口时，非代理请求进入网站，合法代理请求照常使用。

TLS、Reality 的协议层回落均不能与 VLESS 额外加密同时启用。存在不兼容的加密配置时，输入框禁用并提示原因，保存时清空回落配置。

### Reality 原生协议层回落（v1.1.2）

面板保留可选单目标输入框，节点端将其转换为一条原生 `fallbacks` 规则。填写接收解密后数据的后端地址，例如明文 HTTP 网站 `127.0.0.1:8080`；**不会覆盖 Reality 原目标（dest），也不改变 SNI、密钥、Short ID 或 Flow**。

- 普通浏览器或未通过 Reality 鉴权的连接仍转发到原 Reality HTTPS 目标。
- 通过 Reality 握手后，VLESS / Trojan 协议首包或认证失败的连接，才进入协议层回落。
- Reality 和代理协议认证都正确时，继续正常代理。

因此，普通浏览器访问无法验证 Reality 协议层回落是否生效。独立模式使用同一 `fallbacks` 列表语法，并支持多规则；见 [xboard-node-u 独立运行指南](https://github.com/Toto0912/xboard-node-u/blob/main/docs/STANDALONE.md)。

### 升级兼容

面板和节点端需要一并升级到 **v1.1.2**。此前版本将面板 Reality Fallback 用于覆盖 HTTPS 目标；本版有意改为原生协议层回落。旧数据仍保留，但升级前须核对已有 Reality Fallback：HTTPS 伪装目标应配置在 Reality 设置中，协议层回落通常使用明文后端，不要混用端口。回落目标不能指回节点自身监听端口。

此改动不新增数据库列或迁移，不自动删除配置。留空保持原行为；sing-box 继续忽略该服务端字段，客户端订阅不包含它。

## TLS 内容推送保存修复

修复 HY2 等节点的 TLS 内容推送配置保存后，重新打开高级设置却显示为空的问题。兼容原有空证书配置，保存并保留证书、私钥及相应设置。

## 机器安装命令

添加或编辑机器时，可复制的安装命令使用 xboard-node-u 的正式 Release 资源。支持普通 Linux 的 systemd 安装及 Alpine Linux / OpenRC 安装，默认使用 sing-box 内核。

## 默认订阅模板

更新以下三份默认模板：

| 客户端 | 默认模板文件 |
| --- | --- |
| sing-box 1.14 | [default.sing-box.json](../resources/rules/default.sing-box.json) |
| Clash | [default.clash.yaml](../resources/rules/default.clash.yaml) |
| Clash Meta / Stash | [共用 default.clashmeta.yaml](../resources/rules/default.clashmeta.yaml) |

新装面板使用这些默认内容。升级时仅自动替换已知的原版默认模板，保留管理员已自定义的模板及其他类型模板，并避免旧 Redis 缓存继续返回旧默认内容。已有自定义模板需要换用新模板时，可在面板订阅模板设置中自行替换。

## 部署与原版迁移

保留原版数据库、主题及节点通信接口，支持从原版迁移。提供 Linux amd64 / arm64 Docker 镜像 `ghcr.io/toto0912/xboard-u:latest`，Docker 构建使用当前项目源码和固定版本的管理前端资源。

- [aaPanel + Docker 部署](AAPANEL-MYSQL-UPGRADE.md)
- [从原版 Xboard 迁移](UPGRADE-XBOARD-U.md)

Fallback 管理界面扩展在 Docker 构建时自动生成，不修改上游前端子模块。手动从源码构建时，执行 `php scripts/prepare-admin-assets.php` 生成；如果固定的上游资源发生变化，构建会提示需要重新检查扩展。
