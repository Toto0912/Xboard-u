# v2.4 - lastest 二次开发功能说明

面板 v2.4 系列的功能和升级变化按版本列出。此前版本见 [v1.0 至 v2.3 功能说明](v1.0%20-%20v2.3%20二次开发功能说明.md)。

## v2.4.3

- 修复后台列表刷新时群发邮件或批量封禁范围可能改变的问题。用户管理和订单管理均会拒绝空白指派金额，显式填写 0 元仍可建单。源码发行包同步包含修正后的后台页面。
- 修复管理员改密后旧会话仍可用、主题切换后显示或删除判断不一致，以及订单取消后迟到的结账响应重新打开收款界面的问题。
- 零外付换购在确认时按已入账用量复核原折抵金额，避免用户建单后继续消耗流量仍按旧报价开通或返还余额。
- 修复机器子节点连接记录丢失后在线设备数停止更新的问题。今日节点榜及历史统计按站点时区取数，修正跨日统计偏差。

升级前请备份数据库，完成迁移并更新全部面板实例和队列进程，再更新节点。新写入的流量回执会记录来源，便于按保留期清理已完成的旧协议回执。

需要清理历史回执时，先执行 `php artisan traffic:prune-legacy --days=90` 查看符合条件的数量和完成时间范围。根据排障与备份周期选定保留天数，确认备份可恢复后，在低峰执行同一命令并加上 `--execute`。命令只清理超过保留期、已完成且没有剩余任务的旧协议回执。显式批次和来源未知的记录继续用于查重。清理中断后可重跑，默认不定时执行。

## v2.4.2

### 重要修复

- **账号与登录**。找回密码成功后，所有设备的旧会话和此前签发的登录短票一并失效。快捷登录和邮件登录链接只能兑换一次，兑换时会重新检查账号是否已被封禁。
- **工单权限与敏感信息**。通过 Telegram 回复工单时，面板会核对绑定账号的客服或管理员权限，以及工单是否仍然开放。后台审计日志改为记录变更字段名，避免把表单中的节点令牌和支付密钥写入日志。
- **封禁、到期与超额撤权**。批量封禁按同一批用户撤销面板会话并通知节点。到期通知失败后会重试，超额检查中断后可以继续，避免用户到期或用尽流量后仍保留节点权限。节点迁移到另一台机器时，同机其他节点的连接也会保留。
- **流量计费**。跨午夜的倍率时段现在会正确覆盖次日凌晨。完成数据库批次迁移后，面板会将旧节点一次上报的所有流量分块与入账任务放在同一事务中保存，避免只登记部分用户的用量。队列暂时不可用时，已保存的任务可重新派发。旧协议仍无法识别节点重发的整份请求。
- **支付回调**。易支付核对签名中的商户号和金额，支付宝当面付核对签名中的应用 ID 和金额。回调缺少金额会被拒绝。对已保存结账报价的订单，面板按当时含手续费的报价核对实收金额，再开通套餐。
- **余额与邀请返佣**。修复历史负余额抬高订单应付金额的问题，取消订单时只返还该单实际抵扣的余额。邀请人设置 `0%` 时按零计算佣金，只有留空才继承全局比例。已折抵且满足等待期的订单也可进入佣金自动审核，避免漏发。

### Naive 一键订阅

有 Naive 节点使用权限的用户可以直接在「一键订阅」中选择客户端。复制订阅地址或扫码导入也使用同一入口，刷新订阅后即可收到客户端支持的节点。

| 客户端 | 面板下发条件 |
| --- | --- |
| sing-box | 1.14.0 及以上，使用带 Naive 出站和 Cronet 的构建。默认订阅模板以 1.14 为基线。 |
| Hiddify | Android、Windows、Linux、macOS 从 5.5.5 开始下发。iOS 及未报告平台的版本从 5.9.15 开始下发。 |
| Shadowrocket | 语义版本从 2.2.24 开始，若仅报告构建号则从 1959 开始。下发开启 Naive padding 的 HTTP/2 节点。 |
| v2rayN | 7.20.4 及以上，可将「复制订阅地址」得到的地址添加到订阅分组。 |

请在节点启用 TLS，填写客户端可访问的地址和端口；连接地址与证书域名不同时，填写 TLS 服务器名称。客户端需信任该证书。勾选「允许不安全」的节点会被过滤。启用 ECH 的节点只下发到能完整表达该配置的 sing-box 和 Hiddify 订阅。Clash/Mihomo、Stash、Surge、Surfboard 继续接收各自支持的节点。

## v2.4.1

### 流量上报和入账

面板完成批次迁移后，会在握手时向兼容节点宣告批次上报能力。节点把用量和批次编号写入持久化目录，取得匹配回执后才移除该批；面板保存回执与待处理任务，重复投递同一批次只入账一次。旧版节点可以继续使用原协议上报。旧协议的上报没有批次编号，已发送但丢失回执的用量无法追溯去重。PostgreSQL 的账号用量写入已覆盖大于等于 2 GiB 的单次增量与小数倍率。

### 节点名单和权限

面板在批量封禁、自然到期、移组和删除时同步受影响节点的用户。权限组 ID 接受数字和历史字符串格式，名单过滤插件会参与同步。运行时启停名单过滤插件后，应重载相关常驻进程并重新同步节点名单。设备快照按节点推送，节点重连后主动与完整名单对账。

### 支付与人工对账

结账时保存报价、手续费与支付渠道。BTCPay 按结账时的站点币种开具发票，收到回调后向网关确认已足额结算。CoinPayments 核对回调签名、币种和原币金额。相同网关流水的重复通知只开通一次。已取消订单收到款项后留待人工处理，同一订单收到第二笔独立款项时单独登记。可按订单号查询。

```bash
php artisan payment:review-cancelled --trade-no=订单号
php artisan payment:review-additional --trade-no=订单号
```

旧 Coinbase Commerce 内置插件已下架。升级自动停用其已有渠道，保留订单与收款流水；结账页只列出已启用且有可用支付插件的渠道。CoinPayments 是独立渠道。

### 套餐、优惠券与折抵

待付和处理中的普通订单会占用限量套餐名额，礼品卡和注册试用也检查可用名额。限量优惠券在待付时占用，成交核销，取消时释放一次。升级前的订单不回填优惠券占用记录。一次性流量包再次换购按剩余流量折抵，仅把参与计算的订单列作来源。周期套餐按当前连续购买区间计算折抵。开通期间若流量重置失败，订单和套餐变更一起回滚。

### 注册、邀请与前台体验

一次性邀请码与账号创建在同一事务内核销，注册失败后邀请码仍可使用，两人同时使用同一码时只有一人能成功注册。后台编辑邀请人和佣金结算均检查邀请环。购买页显示套餐可用名额，并按套餐状态展示流量重置包。更新管理端和默认用户端的注册、订单及用户编辑流程。

### 升级步骤

1. 升级前备份数据库、`.env` 和持久化目录，并记录当前面板与节点版本，保留对应版本的镜像或安装包。
2. 先更新面板。配套 Docker Compose 会自动执行数据库迁移、启动队列和定时调度。多实例部署请更新所有面板实例。自建队列请确认新版 worker 监听 `traffic_batch`，且 Laravel 调度器每分钟运行。
3. 再将节点更新至 [xboard-node-u v2.4.1](https://github.com/Toto0912/xboard-node-u/releases/tag/v2.4.1)，沿用原节点 ID 和流量持久化目录，以便继续处理尚未收到回执的批次。

## v2.4.0

### 开源现代管理后台（`admin-frontend/`）

使用 React 19 + TypeScript + Vite 6 + Tailwind CSS v4 + Shadcn UI 完整重写并开源管理后台，替换原有的闭源编译产物及 `AdminAssetPatcher` 补丁流程：

- 完整实现 18 个管理后台页面，1:1 保留 Xboard-u 的全部二次开发能力（VLESS / Trojan Fallback、CDN 客户端／服务端分离、HY2 端口跳跃与带宽／伪装配置、Sing-box / Xray 原生自定义出站与路由、机器安装命令、整行拖拽排序模式等），并默认按 ID 升序排列机器、权限组与路由列表。
- 订阅模板（Sing-box、Clash、Clash Meta、Stash、Surge、Surfboard）与节点自定义配置采用瘦身懒加载离线版 Monaco Editor，支持多格式语法高亮、配置结构校验与一键格式化。
- 统一 `1970–2099` 可滚动 Shadcn 日期时间选择器、侧栏与登录页 `X` 品牌图标，并修复移动端仪表盘宽度溢出。
- 深色模式采用深海蓝配色，浅色模式采用暖调牛奶白配色，完整支持简体中文、英语、俄语三语切换。

### 开源现代默认用户端（`user-frontend/`）

使用 React 19 + TypeScript + Vite 6 + Tailwind CSS v4 + Shadcn UI 完整重写并开源默认用户端，编译输出至 `theme/Xboard/assets/`，彻底去除原版闭源 `umi.js`：

- 完整实现登录、注册、找回密码、仪表盘、使用文档、订阅购买与下单、订单支付、节点状态、邀请返利、工单系统、流量明细与个人中心页面。
- 采用与管理端一致的深海蓝（深色）与暖调牛奶白（浅色）主题配色，支持简体中文、繁體中文、English、Iran（波斯语 RTL）、日本語、Tiếng Việt、한국어、Русский 共 8 种语言切换，同时保持对后台上传第三方主题包的兼容。
- Docker 镜像在构建阶段通过 `node:22-alpine`（`admin-builder` / `user-builder`）直接从源码编译管理端与用户端资源，无需额外执行补丁脚本，也不涉及数据库结构变更。
